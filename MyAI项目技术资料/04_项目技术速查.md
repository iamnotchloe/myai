# 项目技术速查

## 一句话项目

> 我在7.17单文档RAG原始项目上，调优了一个面向10份企业金融报告的混合检索问答助手，重点解决重复索引、跨公司错配、中文BM25、引用追溯和分层评测。

## 关键数字

- 原始：1份PDF、26个Chunk、200/50。
- 当前：10份PDF、112个唯一Chunk、500/80、512维。
- Dense：Top10。
- 当前BM25：Top20，已改为中文字符unigram+bigram。
- 当前融合：Dense + BM25使用RRF，`RRF_K=60`。
- Reranker：Top3。
- LLM：temperature 0.1、max_tokens 1024。
- 错误索引：1120条记录、112条唯一正文。
- 修复后：112条记录、112条唯一正文、跨公司错配0。
- 第一版评测：32题，27可回答、5无答案。
- Dense Hit@10：1.000，MRR：0.910。
- 空白BM25 Hit@10：0.370，MRR：0.189。
- 中文字符BM25 Hit@10：1.000，MRR：0.932。
- 字符BM25 + Dense RRF Hit@3：1.000。
- 端到端只测3题：3/3，平均约10.49秒，不能说整体100%。

## 六句话框架

1. 数据决定上限：解析、切片、元数据、去重先正确。
2. 粗召回追求不漏：Dense负责语义，BM25负责精确词。
3. 精排追求靠前：Cross-Encoder把正确证据放进Top3。
4. 生成必须有依据：低温度、拒答、校验和引用。
5. 评测必须分层：召回、重排、生成、拒答、端到端、延迟。
6. 没有冻结测试集不报整体准确率。

## 三个核心优化案例

### 案例1：索引错配

回答对但引用错 → 打印中间结果 → 发现1120/112重复 → 修复构建与公司标签 → 错配降为0。

### 案例2：BM25评测

不是“加了BM25就一定更好” → 单独测两路 → 空白分词Hit@10仅0.370 → 中文字符分词提升到1.000。

### 案例3：完整页引用

小Chunk利于检索但不方便用户核对 → 模型仍用Chunk → 前端展示命中Chunk所属完整PDF页。

## 项目表述注意事项

- 不说整体准确率100%或95%；
- 可以说RRF已接入后端，但不能把27题开发结果说成最终生产指标；
- 不把3题冒烟测试说成正式测试；
- 不说Reranker已经微调；
- 不说MyAI是原始项目；
- 不说金融政务双域已完成；
- 不说SiliconFlow模型是本地部署；
- 不说FAQ/few-shot已经形成成熟数据飞轮。

## 核心优化原则

> 当前最优先的不是盲目换更大的模型，而是把中文分词、融合、分数日志和Golden Set做好，用固定测试集证明每项改动的真实收益。
