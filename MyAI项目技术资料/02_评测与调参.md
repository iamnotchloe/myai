## 一、为什么必须分层评测

最终答案错，不一定是大模型错：

| 现象 | 主要检查对象 |
|---|---|
| 原始TopK没有标准页 | 数据、切片、Embedding、Query、BM25 |
| 原始TopK有，Top3没有 | 融合或Reranker |
| Top3正确，答案错误 | Prompt、模型、计算、上下文利用 |
| 答案正确，引用错误 | 元数据、引用映射、父子切片 |
| 无答案却强答 | 阈值、拒答、幻觉控制 |
| 结果正确但很慢 | 模型加载、同步请求、Reranker、LLM |

所以评测要分成：数据质量、粗召回、精排、生成、拒答、端到端和工程性能。

## 二、怎么知道召回了什么

每次请求至少记录：

```json
{
  "trace_id": "...",
  "question": "...",
  "mentioned_companies": ["..."],
  "dense_topk": [{"file":"...","page":1,"rank":1,"distance":0.31}],
  "bm25_topk": [{"file":"...","page":1,"rank":1,"score":8.7}],
  "fused_topk": [{"file":"...","page":1,"rank":1,"rrf_score":0.032}],
  "reranked_top3": [{"file":"...","page":1,"rank":1,"score":0.91}],
  "answer": "...",
  "latency_ms": {"dense":18,"bm25":5,"rerank":430,"llm":9200}
}
```

网页最终显示的 `source_documents` 只是Reranker后的最终引用，不等于FAISS或BM25原始召回。要判断召回问题，必须看各阶段中间结果。

## 三、Golden Set怎么建

每题至少标注：

- `question`：真实问题或改写；
- `answerable`：知识库能否回答；
- `answer_checks`或标准答案；
- `gold_pages`或`gold_chunk_ids`；
- `category`：事实、事件、比较、治理、无答案等；
- `difficulty`：easy/medium/hard；
- `notes`：单位、歧义、异常说明。

建议最终规模：

- 开发集100-200题，用于调参；
- 冻结测试集100-200题，只在版本定稿时运行；
- 15%-25%无答案题；
- 覆盖错别字、简称、口语改写、多文档比较、时间限制和Prompt Injection。

当前32题只是第一版评测基线，不是最终生产测试集。

## 四、召回指标公式

### Hit@K

```text
Hit@K = TopK至少命中一个标准页面的问题数 / 问题总数
```

适合每题只有一个核心答案页的问答系统。

### Recall@K

```text
Recall@K(q) = TopK找到的相关页面数 / 该问题全部相关页面数
```

例如多公司比较需要2页，Top3只找到1页，Recall@3=1/2。

### Precision@K

```text
Precision@K(q) = TopK相关页面数 / K
```

召回高、精度低表示找得全但噪声多。

### MRR

```text
MRR = mean(1 / 第一个相关页面排名)
```

排名为1、2、5、未命中时：`(1 + 1/2 + 1/5 + 0) / 4 = 0.425`。

### NDCG@K

当页面分为“完全相关、部分相关、不相关”时使用，既考虑相关等级，也考虑高相关页面是否排在前面。

## 五、答案与拒答指标

### 数值准确率

先统一单位，再比较：

```text
(公司, 年份, 指标, 数值, 单位)
```

`1亿元 = 10000万元 = 100000000元`。只比较字符串会把等价答案误判为错误。

### 短答案

- Exact Match；
- Token Precision/Recall/F1；
- 结构化字段正确率。

### 长答案

- Correctness：结论是否正确；
- Completeness：关键点是否完整；
- Relevance：是否真正回答问题；
- Faithfulness：每个事实是否被上下文支持。

```text
Faithfulness = 被引用上下文支持的原子Claim数 / 全部原子Claim数
```

BLEU/ROUGE只能衡量文字重合，不能可靠判断金融事实正确性。

### 拒答

- Refusal Precision：所有拒答中真正无答案的比例；
- Refusal Recall：所有无答案题中成功拒答的比例；
- Refusal F1；
- 无答案幻觉率：无答案却编造内容的比例。

## 六、已经跑出的离线评测

数据：27条可回答题，按PDF页面去重后评测。

### 当前空白分词

| 方法 | Hit@1 | Hit@3 | Hit@5 | Hit@10 | MRR@10 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.148 | 0.185 | 0.259 | 0.370 | 0.189 |
| BGE Dense | 0.852 | 0.963 | 1.000 | 1.000 | 0.910 |
| RRF模拟 | 0.333 | 0.519 | 0.704 | 0.926 | 0.488 |

结论：当前BM25对中文问题几乎没有可靠贡献，还会在RRF模拟中拖累Dense。原因是默认按空格分词，而PDF中文字被整段当成很少的长Token。

### 中文字符unigram+bigram

| 方法 | Hit@1 | Hit@3 | Hit@5 | Hit@10 | MRR@10 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.889 | 0.963 | 0.963 | 1.000 | 0.932 |
| BGE Dense | 0.852 | 0.963 | 1.000 | 1.000 | 0.910 |
| RRF模拟 | 0.852 | 1.000 | 1.000 | 1.000 | 0.920 |

结论：

- 中文分词使BM25 Hit@10从0.370提高到1.000；
- BM25 MRR从0.189提高到0.932；
- RRF Hit@3从0.519提高到1.000；
- 本题集上字符BM25的MRR略高于RRF，说明融合不是自动优于单路，仍需看指标和Bad Case；
- 数据量只有27条可回答题，结果是开发结论，不是最终泛化结论。

### 端到端冒烟测试

- 3题；
- Answer Accuracy：1.000；
- Citation Hit Rate：1.000；
- Citation Recall：1.000；
- End-to-End Correct Rate：1.000；
- 平均延迟：约10.49秒。

三题太少，只能证明评测链路可用，不能写成整体准确率100%。

## 七、每部分为什么这样做、参数怎么调

### 1. PDF解析

为什么PyPDFLoader：当前报告是可复制文本PDF，可以按页抽取并保留页码、source和total_pages。

问题：

- 表格行列可能被打乱；
- 扫描件需要OCR；
- 图表数字不会自然变成结构化文本；
- 页眉页脚可能制造噪声。

下一步：段落走文本切片；表格转换成Markdown/JSON；扫描页OCR；图表用视觉模型；所有内容保留页码与表名。

### 2. 元素级token自适应Chunk

原始200/50容易把公司、年份、指标、数值和解释切开。当前先解析标题、正文句子和表格样式行，再按BGE tokenizer逐元素累计；开发集选择448-token上限和96-token完整元素重叠，避免在元素中间硬切。

不能说500一定最优，应测试：

| Chunk | Overlap | 观察指标 |
|---:|---:|---|
| 200 | 50 | Recall、MRR、答案完整性 |
| 300 | 50 | 同上 |
| 500 | 80 | 旧固定长度基线 |
| 800 | 120 | 上下文完整度和噪声 |
| 元素级token自适应 | 448/96 tokens | 当前实现；表格、标题和句子边界 |

推荐父子切片：200-300字小块检索，命中后把父段落或完整页给生成模型。

### 3. BGE-small-zh-v1.5

为什么：中文检索能力与Mac资源成本平衡，512维、模型较小，120个切片检索足够快。

要实验：

- Query是否添加中文检索指令；
- `normalize_embeddings=True/False`；
- BGE-small/base/M3或Qwen3-Embedding-0.6B；
- Recall@5/10、MRR、编码耗时、内存和索引大小。

### 4. FAISS IndexFlatL2

为什么：只有120个向量，Flat是精确搜索，没有近似检索损失，维护成本最低。

扩展后再考虑：

- HNSW：`M`、`efConstruction`、`efSearch`；
- IVF：`nlist`、`nprobe`；
- PQ：压缩率和量化误差；
- Milvus/Qdrant：动态更新、过滤、权限和多实例服务。

### 5. BM25

为什么：公司名、年份、金额和专业名词需要精确匹配，Dense擅长语义但可能忽略字面细节。

当前最大问题：中文默认空白分词。下一步可选：

- jieba + 财务词典；
- 字符unigram+bigram；
- Elasticsearch/OpenSearch中文分析器。

参数：

- `k1`控制词频饱和，一般从1.2-2.0搜索；
- `b`控制文档长度惩罚，一般从0.5-0.9搜索；
- 用开发集MRR和Hit@K选，不凭感觉。

### 6. RRF融合

BM25分数与向量距离不在同一尺度，不能直接相加。RRF只使用排名：

```text
RRF(d) = Σ 1 / (c + rank_i(d))
```

常用 `c=60`，应测试20/40/60/80。RRF提升稳健性，但本题集上不一定提升Top1，因此要结合Reranker和Bad Case分析。

### 7. Reranker

Embedding双编码器快，适合粗召回；Cross-Encoder联合读取Query和Document，更准但更慢，适合几十条候选精排。

当前Top3是合理起点，但要测试Top1/3/5。必须保留`relevance_score`，否则无法：

- 判断Reranker是否改善排名；
- 校准拒答阈值；
- 分析高分错例；
- 监控分数漂移。

### 8. 拒答阈值0.5

当前用Top3平均Embedding相似度并设置0.5，没有开发集校准。正确方法：

1. 准备可回答与无答案题；
2. 保存Top1、Top3均值、最大分和Reranker分；
3. 扫描阈值；
4. 画Precision-Recall或ROC；
5. 根据业务选择误答成本与拒答成本。

金融场景通常宁可多拒答，也不要编造财务数字。

### 9. 生成参数

- `temperature=0.1`：事实问答追求稳定；
- `max_tokens=1024`：足够回答，但应根据真实答案长度减少成本；
- Top3上下文：控制噪声和Token；
- 3次重试：提高网络稳定性，但可能放大延迟。

需要增加：明确引用格式、单位规范、无证据拒答、Prompt Injection防护和计算步骤校验。

## 十、Qwen3 Embedding/Reranking知识怎么用于项目

语雀资料中介绍了Qwen3 Embedding与Reranking的多种尺寸和训练思想。技术重点不是背模型名字，而是理解它们解决什么问题。

### 1. Instruction-aware Embedding

同一句文本用于“相似句搜索”“问答检索”“分类”时，理想表示可能不同。Instruction-aware模型把任务描述也作为输入，让Embedding知道当前目标是“用中文短问题检索金融报告段落”。

在MyAI中应测试：

```text
无指令：滨江公司的营业收入是多少？
有指令：为这个问题生成表示，以检索能够回答问题的企业金融报告段落：滨江公司的营业收入是多少？
```

只对Query加指令，文档保持原文；比较Recall@5/10、MRR、编码延迟和缓存方式。

### 2. InfoNCE与对比学习

训练目标是让Query靠近Positive、远离Negative。一个batch中的其他文档可作为in-batch negative：

```text
loss = -log exp(sim(q,p+)/τ) / Σ exp(sim(q,p_i)/τ)
```

温度`τ`越小，模型越强调相似度差异，但过小可能训练不稳定。

### 3. Hard Negative为什么重要

随机负例太容易，模型学不到细粒度区别。金融报告中最有价值的Hard Negative是：

- 指标相同但公司不同；
- 公司相同但年份不同；
- 营业收入与净利润混淆；
- 资产负债率与负债比率相似；
- 页面主题相关但不含最终数值。

可以从当前Dense/BM25 Top20中排除标准页后自动采样，再人工复核。

### 4. Embedding模型如何比较

不能只看公开MTEB排名。项目内要比较：

- Hit@K、Recall@K、MRR；
- 512/1024/更高维向量的内存；
- Mac CPU/MPS编码时间；
- 索引构建耗时；
- 中文金融实体和单位的Bad Case。

### 5. Reranker相关性打分

Reranker联合读取Query和候选文档，学习“这段文档是否能回答这个问题”，比单独向量相似度更细致。语雀材料中的yes/no相关性思想，本质上也是把相关性转成可比较分数。

在MyAI中，第一步不是立刻微调，而是先保留API返回的`relevance_score`，测清楚：

- 重排前后MRR变化；
- 正例从Top10进入Top3的比例；
- 正例被错误排出的比例；
- 分数在可回答题和无答案题上的分布。

有足够反馈数据后，才考虑用`query-positive-hard negative`做领域微调。

## 十一、从评测到改进的闭环

```text
收集真实问题
→ 人工标注答案与标准页
→ 分成开发集和冻结测试集
→ 跑每阶段rank/score
→ 按Bad Case分类
→ 一次修改一个变量
→ 在开发集调参
→ 在冻结测试集确认
→ 灰度上线
→ 线上点踩/无结果问题回流
```

Bad Case标签建议：

- `parse_error`：PDF解析错误；
- `metadata_error`：公司、页码或文件错误；
- `chunk_boundary`：答案被切开；
- `dense_miss`：语义召回漏掉；
- `bm25_miss`：关键词召回漏掉；
- `fusion_drop`：融合后排名下降；
- `rerank_drop`：Reranker把正例排掉；
- `generation_error`：上下文正确但答案错；
- `citation_error`：答案对但引用错；
- `refusal_error`：该答不答或不该答却回答。
